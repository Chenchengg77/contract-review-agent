# 评估集标注指南

`gold.json` 是整个系统**唯一的「标准答案」**：抽取准确率、风险判定准确率、忠实度，全部拿它来算。
数字能不能进简历，取决于这里的标注是否可信。

---

## 一、13 类条款（与 `data/playbook/clauses.json` 一一对应）

付款条款 / 违约金 / 争议解决 / 保密条款 / 知识产权 / 合同终止 / 责任上限 / 验收条款 / 交付条款 / 发票条款 / 竞业限制 / 数据合规 / 不可抗力

---

## 二、四态判定规则

| 状态 | 含义 | 典型例子 |
|---|---|---|
| **合规** | 条款存在，且完整覆盖 playbook 的 `must_contain`，无 `red_flags` | 「违约金按日万分之五，最高不超过 20%」 |
| **偏离** | 条款存在，但缺 `must_contain` 要素，或关键内容**留空待填** | 「违约责任：＿＿＿」（比例留空） |
| **缺失** | 整份合同**没有**这类条款 | 承揽合同里没有「知识产权」条款 |
| **冲突** | 条款命中 playbook 的 `red_flags` | 「违约金按日 1%，不设上限」 |

**判定唯一依据是 playbook 的 `must_contain` / `red_flags`**，不是你的直觉。

---

## 三、severity 怎么填

- 命中 `red_flags` → **高**
- 「缺失」→ 用 playbook 里该条款 `severity_rule` 的「缺失整条」档（有的高、有的中）
- 「偏离」→ 一般 **中**（缺要素但还有补救空间）
- 「合规」→ **低**

---

## 四、标注步骤

1. 打开一份合同；
2. 按 13 类条款**逐条过一遍**，问两个问题：
   - 这份合同里有这类条款吗？在**第几条**？（`present` + `evidence`）
   - 相对 playbook，它是合规 / 偏离 / 缺失 / 冲突？（`verdict` + `severity`）
3. `evidence` 填「**第 X 条 + 标题**」，例如 `第十二条 违约责任`；
4. `reason` 写**一句能落到具体要素**的话，不能是「感觉有风险」。

---

## 五、质量红线（面试官会抽查）

- ✅ `present=true` 必须有 `evidence`
- ✅ `verdict=缺失` 的 `evidence` 留空 `""`
- ✅ 每条 `reason` 都能指向合同原文
- ❌ 禁止写「模型判断」「可能存在风险」这类空话

---

## 六、格式

每条合同一个对象，`items` 里 13 条（每类一条，缺一不可）：

```json
{
  "file": "承揽_承揽合同_GF-2000-0303.docx",
  "items": [
    {
      "clause": "违约金",
      "present": true,
      "evidence": "第十二条 违约责任",
      "verdict": "偏离",
      "severity": "中",
      "reason": "违约责任条款存在，但违约金比例与计算方式留空待填"
    }
  ]
}
```

完整示例见 `gold.json`（已含「承揽合同」13 条的完整标注，照这个写）。
