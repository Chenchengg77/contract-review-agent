# 面试速记（Interview Cheat Sheet）

> 面试前 10 分钟翻一遍。原则：**挑 3 个讲透，别铺开 20 个。**

---

## 一、30 秒总述

> "我做的是一套**合同智能审查 Agent**：上传合同 → 自动识别 13 类条款 → 判定风险 → 给出修订建议。
> 技术上分三层：解析、LLM 抽取、规则+语义判定；另外有基于 RAG 的问答，和一套评估体系。"

---

## 二、三个核心能力（记住这三句）

1. **让判定可量化**：403 条金标，抽取 95.53%，判定 91.07%
2. **让 AI 不乱说**：前置护栏（检索阈值 + 意图分类），越界拒答
3. **让系统能维护**：健康检查、失败重试、运行时配置

**另外两条加分项**（被问到技术深度时用）：
4. **让高风险有人兜底**：LangGraph `interrupt` 暂停，人确认后才出报告
5. **让检索有据可依**：BM25 + 向量 + Rerank，用 30 条金标做了 4 策略消融

---

## 三、⭐ 监控管崩溃，评测管算错（必背）

| | 崩溃型错误 | 静默错误 |
|---|---|---|
| 表现 | 抛异常、报错 | 审查"成功"，但结果错 |
| 记录 | 失败记录 | **不进失败记录** |
| 靠什么发现 | **监控**（系统运维） | **评测**（403 条金标） |

**一句话：监控发现「崩了」，评测发现「算错了」，缺一不可。**

**真实例子**：条款正文只取到标题 → 审查"成功"但把有正文的条款判成"缺失" → 失败记录看不到 → **评测对比才发现**（判定准确率 85.36% → 91.07%）。

## 四、每个功能，三句话说清

### 前置拦截（Guardrails）
- **是什么**：防 AI 回答越界问题（天气、写诗）
- **怎么做**：检索阈值（低了直接拒答，**不调模型**）+ 灰区意图分类（OOD 检测）
- **类比**：门口保安——先看是不是本小区的人，拿不准的再打电话确认

### RAG 问答
- **是什么**：只根据合同原文回答，不编造
- **怎么做**：BM25 + 向量双路召回 → RRF 融合 → Rerank 精排 → 塞进提示词 → 要求引用条款号 → 找不到就说"合同里没写"
- **降级**：没配 embedding key 就退回纯 BM25，接口失败也退回

### 混合检索（有消融数据撑腰）
- **是什么**：关键词召回 + 语义召回，融合后重排
- **数据**：30 条金标，纯 BM25 Hit@3 63.3% → 混合 80.0% → 加 Rerank 后 Hit@1 63.3%、MRR 0.726
- **类比**：两个实习生抽简历——一个只会按关键词搜（BM25），一个懂语义（向量），把两人的结果合并再让主管（Rerank）拍板

### LangGraph 人工确认（human-in-the-loop）
- **是什么**：高风险条款不让机器直接下结论，暂停等人确认
- **怎么做**：审查编成状态图（parse→extract→assess→**confirm**→report），confirm 里 `interrupt` 暂停，人点确认后 `Command(resume)` 从断点继续
- **类比**：飞机起飞前的机长确认——系统把检查做完，最后一步必须人签字

### 工具调用（function calling）
- **是什么**：模型能主动调 4 个只读工具：取条款原文 / 查法条 / 算金额 / 读审查结论
- **为什么**：模型算数不可靠，违约金必须交给代码算；查法条要引真条文
- **降级**：模型不支持 tool calling 就退回普通 RAG

### 审查上下文
- 审查结果存数据库；问"哪条高风险"时，把审查摘要注入上下文

### 人设语气
- system prompt 写人设 + 语气规则（用"我/你"、先说结论、别说"综上所述"）

### 主动追问 / 记住用户
- 前端 + 数据库的小功能，不是模型能力

## 五、可能的追问 & 回答

| 追问 | 回答 |
|---|---|
| 为什么用向量检索？ | 纯关键词对口语问法召回差（"钱什么时候给我"命中不了"付款条款"）。我用 30 条金标做了消融：纯 BM25 Hit@3 63.3%，混合 80%，加 Rerank 后 Hit@1 63.3% |
| 为什么还保留 BM25？ | 纯向量的 Hit@3 只有 70%，比混合低 10pt——条款号、金额这类精确匹配靠关键词更稳 |
| 意图分类不是多花一次钱？ | 只在灰区调，高分直接放行，大部分问题零额外成本 |
| 阈值为什么定 5 和 8？ | 我实测过：正常问题 8~16 分，越界问题 3~7 分，取中间做灰区 |
| 这些是你原创的吗？ | Guardrails / OOD / RRF / HITL 都是业界做法，我实现的是"两层阈值 + 灰区分类""混合召回 + 精排"这些组合 |
| 出问题怎么修？ | 发现（告警）→ 定位（错误详情）→ 修（重试）→ 回滚（恢复默认） |
| 模拟故障是真的吗？ | 是演示开关；真实 bug 我修过（正文提取，85% → 91%） |
| 所有合同都能审吗？ | 不是，只面向**商务合同**的 13 类条款；劳动合同会误报 |
| LangGraph 状态存哪？ | 现在 `MemorySaver`（内存），重启会丢；上生产换 SqliteSaver 落库——这是已知局限 |

## 六、演示脚本（3 分钟）

1. **评估页** → 版本对比（85% → 91%）+ **检索消融表**（4 种策略）
2. **审查页** → 勾「人工确认」审一次 → 停在待确认 → 确认后出报告
3. **AI 对话** → 问"按车价 10 万、违约金 20% 是多少钱" → 出现工具标签
4. **管理端运维** → 模拟故障 → 告警 → 重试 → 清理
5. （可选）**坏文件** → 真实失败 → 重试也没用 → "要用户重传"
