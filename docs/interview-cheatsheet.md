# 面试速记（Interview Cheat Sheet）

> 面试前 10 分钟翻一遍。原则：**挑 3 个讲透，别铺开 20 个。**

---

## 一、30 秒总述

> "我做的是一套**合同智能审查 Agent**：上传合同 → 自动识别 13 类条款 → 判定风险 → 给出修订建议。
> 技术上分三层：解析、LLM 抽取、规则+语义判定；另外有基于 RAG 的问答，和一套评估体系。"

---

## 二、三个核心能力（记住这三句）

1. **让判定可量化**：403 条金标，抽取 95.53%，判定 91.07%
2. **让 AI 不乱说**：前置护栏（检索阈值 + 意图分类），越界拒答
3. **让系统能维护**：健康检查、失败重试、运行时配置

---

## 三、⭐ 监控管崩溃，评测管算错（必背）

| | 崩溃型错误 | 静默错误 |
|---|---|---|
| 表现 | 抛异常、报错 | 审查"成功"，但结果错 |
| 记录 | 失败记录 | **不进失败记录** |
| 靠什么发现 | **监控**（系统运维） | **评测**（403 条金标） |

**一句话：监控发现「崩了」，评测发现「算错了」，缺一不可。**

**真实例子**：条款正文只取到标题 → 审查"成功"但把有正文的条款判成"缺失" → 失败记录看不到 → **评测对比才发现**（判定准确率 85.36% → 91.07%）。

---

## 四、每个功能，三句话说清

### 前置拦截（Guardrails）
- **是什么**：防 AI 回答越界问题（天气、写诗）
- **怎么做**：检索阈值（低了直接拒答，**不调模型**）+ 灰区意图分类（OOD 检测）
- **类比**：门口保安——先看是不是本小区的人，拿不准的再打电话确认

### RAG 问答
- **是什么**：只根据合同原文回答，不编造
- **怎么做**：BM25 检索段落 → 塞进提示词 → 要求引用条款号 → 找不到就说"合同里没写"

### 审查上下文
- 审查结果存数据库；问"哪条高风险"时，把审查摘要注入上下文

### 人设语气
- system prompt 写人设 + 语气规则（用"我/你"、先说结论、别说"综上所述"）

### 主动追问 / 记住用户
- 前端 + 数据库的小功能，不是模型能力

## 五、可能的追问 & 回答

| 追问 | 回答 |
|---|---|
| 为什么不用向量检索？ | 合同短，关键词够用；向量要调 embedding，成本和复杂度都高 |
| 意图分类不是多花一次钱？ | 只在灰区调，高分直接放行，大部分问题零额外成本 |
| 阈值为什么定 5 和 8？ | 我实测过：正常问题 8~16 分，越界问题 3~7 分，取中间做灰区 |
| 这些是你原创的吗？ | Guardrails / OOD 是业界做法，我实现的是"两层阈值 + 灰区分类"这个组合 |
| 出问题怎么修？ | 发现（告警）→ 定位（错误详情）→ 修（重试）→ 回滚（恢复默认） |
| 模拟故障是真的吗？ | 是演示开关；真实 bug 我修过（正文提取，85% → 91%） |
| 所有合同都能审吗？ | 不是，只面向**商务合同**的 13 类条款；劳动合同会误报 |

## 六、演示脚本（3 分钟）

1. **评估页** → 版本对比（85% → 91%）+ 前置拦截对比
2. **审查页** → 审一次 → 主动追问气泡出现
3. **AI 对话** → 问"哪条高风险" → 能答（证明注入上下文）
4. **管理端运维** → 模拟故障 → 告警 → 重试 → 清理
5. （可选）**坏文件** → 真实失败 → 重试也没用 → "要用户重传"

---

## 七、被问住了怎么办

- ❌ 别编
- ✅ "这块我还没深入，回去查一下"
- ✅ 把问题转回熟的："实现上我主要关注 X，您想了解哪块？"

## 八、⚠️ 最危险的三句话（千万别说）

| ❌ 别说 | ✅ 应该说 |
|---|---|
| "RAG 只检索了标题" | "**审查判定**取正文的函数只取了标题行，RAG 本身正常" |
| "我能维护整套系统" | "我做了**可观测性 + 可控制性**" |
| "所有合同都能审" | "面向**商务合同**的 13 类条款审查" |
